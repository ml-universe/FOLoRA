# 实验产物溯源（审稿人/复现者先读这一页）

本仓库 `experiments/` 下混有**多个协议、多个代码版本**的历史 run。论文 Table 1 只用了其中
一个子集。这份文档说明「哪些 run 是论文口径、哪些不是、为什么」。

---

## 1. 论文口径（唯一权威）

| 项 | 值 |
|---|---|
| 数据集 | CIFAR-100、ImageNet-R |
| 划分 | 20 任务 × 5 类，类增量（class-IL） |
| epoch / batch | 5 / 32 |
| LoRA rank / alpha | 16 / 16（`lora_rank` 指 adapter 秩） |
| backbone | `vit_b_16`（冻结） |
| 评估协议 | **冻结/适配特征 + 最近类均值（NCM）** |
| 显著性 | **paired t-test on common seeds** |
| 主配置 FOLoRA | `v2f_l3_k64`（λ=3、保护方向 k=64） |

**论文正文与 Table 1 的全部数字来自 `reports/ncm/{benchmark}/*.json`**，
不是 `experiments/*/results.json`。

---

## 2. ⚠️ 两个同名字段 `final_acc_cil`（对外最易踩的坑）

| 路径 | 含义 | CIFAR-100 量级 |
|---|---|---|
| `experiments/*/results.json` → `final_acc_cil` | 随任务增长的**线性分类头** CIL 准确率（旧口径） | ~0.07（如 0.0714） |
| `reports/ncm/*.json` → `final_acc_cil` | **NCM** 协议准确率（论文口径） | ~0.76（如 0.7578） |

字段同名，量级差一个数量级。任何直接读 `experiments/` 的脚本拿到的都不是论文数字。

`reports/ncm/` 缓存由 `python -m scripts.eval_ncm_sweep --benchmark <bench>` 生成（零 GPU）。

## 3. 非论文口径的 run 家族（**勿引用**）

`scripts/significance.py::load_runs_ncm` 会按 `expected_proto(method)` 自动过滤下表全部 run
——过滤依据是**逐 run 的回读 `config.json`**，不能只看 `num_tasks`（见第 4 行 `pilot20` 的教训）。

| run 家族 | 偏离点 | 为何排除 |
|---|---|---|
| `*/pilot20` | `num_tasks=20` 但 `epochs=20` | 任务数看着对，epoch 是 4 倍；精度低 5–10 点，混进来结论全错 |
| `*/t50_*`（ewc / seq / folora_v2） | `num_tasks=50` | 不同任务数，不可与 20 任务比较 |
| `*/ep20`、`ep20_inr`、`pool100_len8_ep20[_inr]` | `epochs=20` | prompt 类方法本来就 20 epoch，其余方法 20 epoch 属另一套设置 |
| `folora/*`（**v1**） | 方法为 v1，正则项退化 | README「方法」表已标注**不要用它跑实验** |
| `folora_v2/v2_l*_k*`、`v2f_l*_k*` 中 `tasks=10, epochs=2, rank=8` 者 | 10 任务 / 2 epoch / rank 8 | 早期小规模试跑 |
| `folora_v2/probe_l10_k16` | 单次探针 | 非主表配置 |
| `ewc/ewc_ref` | `10t / 2e / r8`，n=1 | 见下节 |
| `seq/vdc_seq`、`olora/vdc_olora` | 协议**与主表一致**（20t/5e/r16），故 `expected_proto` **不会**过滤掉它们 | 2026-10-03 版本漂移诊断的重跑 run，n=1。**重跑 `significance --all-configs` 前须把它们排除**，否则会作为额外消融行混进论文产物。它们的 NCM 标量缓存在 `reports/ncm/imagenetr/*__vdc_*__seed0.json`，矩阵在 `reports/ncm_matrix_vdc/`（刻意与画图用的 `reports/ncm_matrix/` 分开） |

## 4. `ewc/ewc_ref` 专条（论文未引用）

```
experiments/cifar100/ewc/ewc_ref/seed0/config.json
  {"num_tasks": 10, "epochs": 2, "lora_rank": 8, "ewc_lambda": 100.0, "tag": "ewc_ref"}
```

- 这是 EWC 调参期的**参照点**，协议与主表**不同**（10 任务 / 2 epoch / rank 8），且只有 `seed0`（n=1）。
- **不在**论文 Table 1 中，也不参与显著性检验。
- 论文里 EWC 的判据基线是 `ewc/default`（λ=100，`20t/5e/r16`，n=10），**不是** `ewc_ref`。
  两者都写 `ewc_lambda=100`，仅凭 λ 无法区分——必须连同 `num_tasks`/`epochs`/`lora_rank` 一起看。
- 另一个易混项：`ewc/ewc_lam100`（λ=100，主协议）只有 `seed0`。同 λ 下 `ewc/default` 有 10 个 seed，
  需要多 seed 时用后者。

## 5. 代码版本批次（写作时须留意）

- CIFAR-100 的 `v2f_eq_*`（等权消融）全部落盘于 **2026-09-25 之后**，用的是 RMS 齐次化后的
  加权重构（`methods/folora_v2.py::_equalize_row_weights`）。此前用算术平均 σ̄ 的旧构造
  **尺度没对齐**（实测总权重比仅 0.248），其产物已归档，**不要与现产物混算**。
  据此，等权消融是「同总权重、不同分配」的干净对照。
- ImageNet-R 上 `seq` / `olora` 的基线 run 早于 `folora_v2` / `ewc` 三周（09-03/05 vs 09-25/26），
  即**只有基线一侧是旧代码**。这正是论文 §5.3 中 T=1 异常（seq T=1 = 79.32 反而低于 FOLoRA
  的 87.80，而同批 FOLoRA/EWC 只差 1.18 点）最可能的成因。
  **状态：正在用当前代码重跑 `seq` 与 `olora` 做版本漂移诊断（tag `vdc_seq` / `vdc_olora`）。**
  结论未出前，不要把 T=1 异常解释成 "RNG 分叉" 或 "方法构造差异"。
- 同一 seed、同一 config 的**重跑本身有 1.3–1.5 点抖动**；可复现性下限按 1.29 点计。
  小于该幅度的差值不要叙述成效应。

## 7. ⚠️ `reports/ncm_matrix/` 的 `acc_cil[t][j]` 不是「任务 t 之后」

**这条影响 `paper/` 的 Fig 2/3 与 §5.2 一段推论，务必先读。**

`checkpoint.pt` 里**只有终态**（`task_id=19`，单个 `model_state`，无逐任务快照），
而 `scripts/eval_ncm.py::ncm_cil_eval` 只接收**一对**特征张量。所以

```
acc_cil[t][j]  ≠  「学完任务 t 之后，用当时的模型，在任务 j 测试集上的准确率」
acc_cil[t][j]  =  「用【终态模型】的特征，以任务 0..t 的训练集样本估计类均值，
                    在任务 j 的测试集上、以 0..t 全部类为候选做最近类均值分类」
```

`plot_forgetting_curve.py` 的 docstring 第 7 行按前者描述，前提不成立。

**受影响的**：Fig 2/3 的横轴（标 `tasks learned`，实际不是时间）；
§5.2 里由曲线形状推出的两句（「retention rather than initial learning」、
「ordering already present on the first task … not an advantage that compounds」）。

**决定性的旁证**：纵轴 A 从 t=0 到 t=19 的落差，三个方法几乎一致
（seq 20.5 / FOLoRA 21.4 / O-LoRA 20.7 点）。若为真轨迹，无保护的 seq 落差应远大于 FOLoRA。
⇒ 落差来自**候选类数从 5 涨到 100**，与时间/遗忘无关。

**不受影响的**：Table 1/3/4 全部数字。`final_acc_cil` = 第 19 行均值
= 「终态模型、100 类候选」的标准类增量 NCM 指标，正是该报的量（`consistency_vs_ncm` Δ=0）。

**另一个独立的现象**：INR 上 `seq` 与 `folora_v2` 的 task-0 **head** 准确率 16 位完全相同
（`0.8813559322033898`，因 task 0 两者正则项都未生效、同 seed ⇒ 训练逐位一致），
而它们的 NCM `acc_cil[0][0]` 差 8.5 分（79.32 vs 87.80）。
这正是上面语义的直接后果——该读数已经含遗忘。

**为不在主表的 run 补算矩阵**（如版本漂移诊断的 `vdc_*`，不在 `MAIN_TAGS` 里）：

```bash
python -m scripts.eval_ncm_matrix_extra      # 产物写入 reports/ncm_matrix_vdc/
```

**版本漂移诊断结论（2026-10-03）**：用当前代码重跑 `seq`/`olora`，
NCM T=1 = 78.98 / 65.08，对旧值 79.32 / 65.08（Δ = −0.34 / 0.00）⇒ **基线可复现，版本漂移排除**。
最终值偏差 +0.60 / −1.03，均在 1.29 点可复现性下限内。详见
`Desktop/FOLoRA-诊断结论-版本漂移排除与曲线口径.md`。

## 8. ⚠️ P0-1：O-LoRA / InfLoRA 的旧 checkpoint 只存了**末个** adapter

**这条影响 Table 1 里 O-LoRA 与 InfLoRA 两整行的数字，务必先读。**

`methods/multi_lora.py` 在保存时只写了**最后一个任务**的 adapter，于是
`checkpoint.pt` 的 state dict 只覆盖 `.adapters.19.`，其余 19 个任务的 adapter 缺失。
评估端加载时 48 个 key 期望、实到 26 个，缺的 18 个**被静默跳过**——所以评测的模型
**不是**训练产出的模型。受影响 run 共 **49** 个（cifar100: InfLoRA 8 / O-LoRA 23；
imagenetr: InfLoRA 6 / O-LoRA 12），逐条清单见
[`docs/p0-1-affected-runs.txt`](p0-1-affected-runs.txt)（表头写明了 49 / 35 / 47 三个数的关系）。

**49 与 35 不是矛盾，是范围不同**：49 是扫描时命中的全部 run，其中含非论文协议家族
（`pilot20`/`ep20`/`ep20_inr`/`olora_mean`/`vdc_olora`/`fix1_probe`），这些本来就不在
Table 1 里、无需重跑；**35** 是其中属论文口径、由 `retrain_fix1.py` 重跑的子集（8 组）。
磁盘现存 seed 目录为 47 = 49 − 2（清单里 `_corrupt_seed2/3` 两条已被隔离移除，保留在
清单中以便 49 可核对）。

**已产生的后果（截至 2026-10-03，尚未修正完毕）**：

- 现存论文 Table 1 中 O-LoRA、InfLoRA 两行的数字来自**污染 checkpoint**；
- 摘要/正文里「$\sim\!18\times$ fewer trainable parameters」以外的 O-LoRA 差值叙述、
  以及从 O-LoRA 正交变体推出的 **`+9.93`** 那个数，同样待用重跑值重新导出；
  （该数的**归属**已于 2026-10-04 查清并修正了正文写法——见 [§10](#10-逐-seed-同号三处断言产物已可独立复核顺带查出一处配错运行)）
- Fig 2/3 中 O-LoRA 曲线同理。

**处理方式：重跑写新 tag，旧 run 一律保留**（旧 checkpoint 是「当时确实这么跑的」
唯一物证，删掉就无法证明这条缺陷存在过、也无法核对修复效果）。

- 重跑脚本：`python -m scripts.retrain_fix1`（逐 run 回读自己的 `config.json` 重放，
  新 tag = 原 tag + `_fix1`，例如 `olora/default` → `olora/default_fix1`；幂等，
  已有 `finished` 的会跳过；`--dry-run` / `--only bench:method:tag` 可选）；
- 进度/ETA：`python -m scripts.retrain_status`（**不依赖日志缓冲**，直接扫文件系统）；
- 脚本内有 `check_replayable()` 断言：若某 run 的配置里有 CLI 未暴露、且偏离 `CLConfig`
  默认值的字段，会直接 `SystemExit` 而不会静默跑出一个「看着像但不是」的复现。

**注意：重跑结果与旧值不会相同，这是预期的，不是回归失败。** 该流水线即使固定 seed
也不可复现（`set_seed` 设了 `cudnn.deterministic` 但没设
`torch.use_deterministic_algorithms(True)`；AMP 与原子累加的反向 kernel 本身非确定）。
实测同 seed 同代码的探针 run 从 task 0、epoch 0 就开始分叉。
⇒ **任何「逐位比对」式的回归判据在本项目一律无效**，只能比区间重叠 / 配对检验。

**不受影响的**：EWC、FOLoRA(=Seq-LoRA+正则)、Seq-LoRA、L2P、CODA-Prompt、SimpleCIL
各行的数字，以及整张 EWC-λ 表——这些方法不走 `multi_lora.py` 的逐任务 adapter 路径。
故 §5.4 中 EWC 与 FOLoRA 的 GAP 对比数字**已经是最终值**。

## 10. 「逐 seed 同号」三处断言：产物已可独立复核；顺带查出一处**配错运行**

论文有三处「每个 seed 的差值都同号」这类断言，原先只落盘**聚合均值 + p 值**，无法从
`reports/` 独立复核。`scripts/significance.py::compare()` 现已为每行落盘
`per_seed_deltas`（逐 seed 差值，百分点）、`n_positive` / `n_negative` / `n_zero`、
`same_sign`。**判据口径**：`same_sign = (n_pos+n_neg>0) and (n_pos==0 or n_neg==0)`，
`n_used<2` 时 `per_seed_deltas` 为空且 `same_sign=False`（「无证据」不等于「同号」）。

2026-10-04 由 `reports/significance_all_paired.json` 复核（对比臂 = 主配置
`v2f_l3_k64`），三处**全部为真**：

| 论文位置 | 断言 | 复核结果 |
|---|---|---|
| §5.2 | INR vs EWC $\lambda{=}100$：$p=0.0002$，十个逐 seed 差**全正** | $n{=}10$，`n_positive=10`/`n_negative=0`，$p=0.00021$ ✓ |
| §5.2 | CIFAR 对四基线：均值差 $+3.61\sim+13.07$，$p\le0.002$ | 四个基线 delta $=3.61/4.67/8.18/13.07$，$\max p=0.00159$ ✓ 全同号为正 |
| §5.2 | INR 对四基线：均值差 $+7.45\sim+22.13$，$p\le0.003$ | $=7.45/7.58/16.89/22.13$，$\max p=0.00221$ ✓ 全同号为正 |

⚠️ **但复核时查出一处配错运行（已在正文修正）**：`+9.93` 的产状是
`olora/olora_orth_l0.1` 与 `olora_orth_l1` **两个独立运行**（逐 seed 值不同，非同一
次的别名），二者均值都约 $68.44$、配对 $p$ 却不同：

| base_tag（INR/CIFAR） | CIFAR acc | CIFAR $\Delta$ | $p$ | INR acc |
|---|---|---|---|---|
| `olora_orth_l0.1` | $68.4400\pm0.5048$ | $+9.93$ | **0.0054** | $48.14$ |
| `olora_orth_l1` | $68.4367\pm1.0681$ | $+9.93$ | **0.0120** | $48.48$ |

原文那句把 $68.44\pm0.50$（**取自 l0.1**）与 $p=0.012$（**取自 l1**）并置成同一个变体，
属「数字配错配置」一类（同 $\lambda{=}10$ 的 $+0.46$ 事故）。已改为两个强度都写明、
两个 $p$ 都给出，并声明引用其中较弱的一个。**注意**：这两个变体属
[§8](#8--p0-1olora--inflora-的旧-checkpoint-只存了末个-adapter) 的 P0-1 污染族，
$+9.93$ 本身**仍待重跑后重新导出**——本节确认的是它的**归属**与正文的**写法**。
